# オンライン対戦の改善（中継サーバー・部屋主の交代・ひとこと）

- 管理番号: #0003
- 種類: ENH（機能改善）
- 対象: オンライン対戦（NET）
- 作成日: 2026-09-15
- 関連: なし（オンライン対戦の初版はコミット c2ecaf2）

## 概要

オンライン対戦の弱点だった3点を直した。つながりにくい回線向けに中継サーバー（TURN）を設定できるようにした。部屋主が抜けても残った人で対局を続けられるようにした。定型文だけを送る「ひとこと」チャットを足した。

## 対象ファイル

- `index.html`（アプリ本体。変更はすべてここ）
- `README.md`（オンライン対戦の仕組み・中継サーバーを使う手順・直近の追加）

## 変更内容

### 1. 中継サーバー（TURN）の設定

「みんなで対戦」→オンライン→「つながりにくい時（中継サーバーの設定）」に、次のどちらかを貼って保存する。

- Metered の「認証情報を取得するURL」（`https://〇〇.metered.live/api/v1/turn/credentials?apiKey=…`）
- 各社の接続情報のJSON（`urls`・`username`・`credential`）

仕組みと注意点は次の通り。

- 貼った内容は保存時に形を確かめる。ブラウザが受け付けない項目（`turn:` 以外、`username` なし、53番ポート）は捨てる
- 「接続テスト」で、直接接続と中継（UDP・TCP・TLS 443番）の可否を ○×で表示する
- 部屋を作った人の中継の一覧は、対局開始時に参加者にも渡す。部屋主が交代した後も同じ中継を配る
- 参加者として設定した中継は、その人が交代で部屋主になっても自分の接続にだけ使い、ほかの人には配らない
- PeerJS が標準で使う無料の公開中継（turn.peerjs.com）も使う。接続設定を渡すと PeerJS 標準の中継が外れていたので、明示的に入れ直した
- 登録・契約は利用者が行う。アプリには鍵を入れていない。手順は README の「中継サーバーを使う手順」

### 2. 部屋主の交代

部屋主の端末が落ちても、やめても、残った人の端末が部屋主を引き継いで続ける。

| 起きたこと | 動き |
|---|---|
| 局の途中で部屋主が落ちた | その局を配り直す（点数・本場・供託は局の始め） |
| 和了・流局の結果画面で部屋主が落ちた | 結果を反映して次の局から |
| 終局の直後に部屋主が落ちた | 新しい部屋主の画面で終局表示 |
| 部屋主が対局中に「対戦をやめる」を押した | すぐに引き継ぐ（待合室・終局の後なら部屋を閉じる） |
| 自分の回線だけが切れていた | 今の部屋に戻る（交代しない） |
| 部屋が2つに割れた（旧部屋主が実は生きていた等） | 人の多い部屋（同じ人数なら世代の大きい部屋）にまとまる。移る側の部屋主が参加者を連れて移る |

仕組みは次の通り。

- 部屋主は、局の開始時と点数が決まった直後に「全員に公開済みの情報だけ」の控えを送る。控えには点数・親・本場・供託・席の名前・合言葉のハッシュが入る。手牌と山は入れない
- 部屋主との接続が切れた参加者は、まず今の部屋と次の部屋に問い合わせる。部屋IDは `suimj-room-コード`、`-1`、`-2` と世代ごとに変わる
- どこも答えなければ、控えの順番で時間をずらして次の部屋IDを取りに行く。仲介サーバーは同じIDを1人にしか登録させないので、新しい部屋主は必ず1人になる
- 画面を裏に回した端末は「離れています」を相手に知らせ、その間は切断とみなすまで90秒待つ
- 通信切れの席がある部屋主は、10分間、前後の世代の部屋を20秒ごとに探す。両方が同時に移らないよう、仲介サーバーの名前（`…-merge`）を鍵にして1人だけが動く
- 参加者は、今いる部屋と同じ世代の控えだけを受け取る（別の部屋の古い控えで交代しない）
- 通信の版を 2 に上げた。古い版の端末とは待合室で「アプリの版が違います」になる

### 3. ひとことチャット

- 対局中は上部の「新局」ボタンが「ひとこと」になる。オンラインでは新局はメニューと同じ動きだったため
- 定型文は8種（よろしく・ナイス！・おしい！・うわー・考え中…・ごめん・ありがとう・おつかれ）
- 送るのは番号だけで、自由入力はない。部屋主が番号を確かめてから配る。1人2秒に1回まで
- 吹き出しは、各端末で見えている席の位置に出す。席ごとに色を変える
- 和了・流局・終局の画面からも送れる。結果画面を開いている間に届いたものは、画面の下に出す
- メニューの「ひとことチャット：表示しない」で、ボタン・表示・音をすべて止められる

### 4. その他

- 参加者の端末では効かない「速度」ボタンを隠した
- 手元の確認用サーバー（localhost）では Service Worker を登録しない。同じ番号で動かした別アプリの記憶と混ざるため

### 5. コードレビューで直した点

複数の視点で読み合わせるレビュー（見つける役と、反証を試みる役）で次の不具合が確認され、直した。

- 別の部屋から戻った人が、新しい世代の古い控えを持ち続け、次の交代で古い点数から再開してしまう
- 交代先へつなぐ途中で仲介サーバーのエラーが出ると、打ち切りのタイマーが消えて「部屋主が交代します」の画面のまま止まる
- 両方の部屋に人が残る割れ方をすると、二度とまとまらない
- 待合室で抜けた人が、対局が始まった後にCPUの席を乗っ取れる
- 交代で部屋主になった端末の中継の取り直しで、引き継いだ中継が消える。参加者として設定した中継が全員に配られる
- スマホ幅で左右の席の吹き出しが重なりうる

## 確認URL

| 環境 | URL |
|---|---|
| ローカル | http://localhost:8765/index.html（確認用に `python3 -m http.server 8765`） |
| 本番 | https://kiyotake1229.github.io/mahjong/ |

確認した内容（ブラウザの3〜4タブを別々の端末として使用）：

- 部屋主を強制終了 → 参加者の1人が約8秒で新しい部屋主になり、局を配り直して続行
- 自分側だけ接続を切る → 約3秒で同じ部屋に戻る（新しい部屋はできない）
- 流局画面で部屋主を強制終了 → 東2局1本場から、流局後の点数で続行
- 終局直後に部屋主を強制終了 → 新しい部屋主に終局表示、「同じメンバーでもう一度」も動く
- 部屋主が「対戦をやめる」 → 約2秒で引き継ぎ
- 部屋が2つに割れた状態（部屋主＋1人 と 2人） → 世代の大きい部屋に4人がまとまる
- 部屋が2つに割れた状態（片方が部屋主だけ） → 人のいる部屋に合流
- 交代後に参加者がページを再読み込み → 同じ席に戻る。見えるのは自分の手牌だけ
- ひとこと：参加者の端末（自分が席0以外）でも、送り主の席の位置に吹き出しが出る
- ひとり用・この端末で交代・物語の掛け合いの吹き出しに影響がない
