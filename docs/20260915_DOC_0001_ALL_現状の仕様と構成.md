## 概要

雀荘「翠」を舞台にした物語つきの4人打ち麻雀。1つの HTML ファイルで動く Web アプリ（PWA）で、道場・ストーリー・CPU との自由対局・みんなで対戦（この端末で交代／オンライン）がある。GitHub Pages で公開中で、遊べる状態。iOS アプリ化は未着手。コミット 7da34fc 時点の内容。以後の変更は #0004 以降の文書に記録する。

## 仕様

### 画面と機能

#### 起動の流れ

- URL に `#room=部屋コード`（6文字）があれば「みんなで対戦」画面を開く（招待リンク）
- 端末に `mjHelpSeen` があれば、自由対局の卓から始まる（自由対局を始めた・ルールブックを閉じた端末）
- それ以外は雀荘メニュー（`showStory`）。主人公が未設定なら序章（`showPrologue`）から
- 上部の「メニュー」ボタン（id `helpBtn`）でいつでもメニューを開ける。対局中なら「対局にもどる」で再開できる

#### 入口の一覧

| 入口 | 中身 | 画面を出す関数 |
|---|---|---|
| 道場 | 8レッスン、第0章の復習、自由対局、ルールブック | `showDojo` |
| ストーリー「雀荘 翠」 | 序章〜第六章。会話と対局で進む | `showStory` |
| 自由対局 | CPU 3人と半荘 | `newHand(false)` |
| みんなで対戦 | この端末で交代／オンライン | `showVersus` |

#### 道場

- レッスンは `LESSONS` の8つ。牌のきほん／はじめての和了／リーチとロン／鳴きと守り／役とドラ、上級としてフリテン／点数の見方／七対子
- クイズとクリア称号がある。クリアの記録は `mjLesson_<id>`
- ほかに「はじめの一歩（第0章）」「ストーリーで学ぶ」「自由対局を始める」「説明を読む」のボタン
- レッスン中の解説は、卓の上の吹き出し（id `coach`、関数 `coachShow`）

#### ストーリー「雀荘 翠」

章の構成。メニューにはクリア済みと次に遊べるものだけが並び、次の章は「？？？」の1行だけ出る（ネタバレ防止）。

| 章 | 中身 | 開く条件 |
|---|---|---|
| 序章 | 主人公の名前（8文字まで）と出自を選ぶ | 最初 |
| 第0章 はじめの一歩 | 3節（何をするゲームか／配牌・山・ツモ／あがりの形）。データは `ZERO` | 序章の直後 |
| 第一章 翠の教え | 8節（入店／初めての和了／早打ちのハヤト／シズカの守り／勝負師ゲン／牌効率／押し引き／翠の一員）。第三〜七節の後に「1局だけ実戦」を選べる（`PRACTICE`、飛ばせる）。終節は常連3人と1局打ち、あがれば完了。データは `STORY` と `STORY_EXTRA` | 第0章クリア |
| 第二章 腕試し | ハヤト → シズカ → ゲン（各1半荘） | 第一章クリア |
| 第三章 岐路 | 買収の申し出（会話）で道を選ぶ。「翠を守る」ならレン戦、「新しい翠」ならクロダ戦。選び直せる | 第二章の第三戦を突破 |
| 第四章 最後の一局 | マスター戦。結末が4つ | 第三章の第四戦を突破 |
| 第五章 黒い手 | 第一夜カラス → 第二夜 堂本 → 決戦 堂本。相手がイカサマをする | 第四章クリア |
| 第六章 白い塔 | 序（会話）→ ミナト → ハヤト（鷲尾側）→ 決戦 鷲尾 | 第五章クリア |

第二章以降の並びは `storyPath()` が返す配列の順（`ST.hayato` … `ST.washio`）。

出自と難易度（`ORIGINS`、反映は `castStage` / `bossLevel` / `gaugeAdd`）。

| 出自（id） | 難易度 | 効果（第二章以降の対局） |
|---|---|---|
| 元ギャンブラー（`gambler`） | 難しい | 持ち点2万点から。スキルゲージ0.5倍。ボス以外の相手も強め |
| 祖父の店を探す学生（`student`） | 標準 | なし |
| 大手チェーンの新人（`clerk`） | やさしい | スキルゲージ2倍。賭けを流すとボスが1段階弱い。マスター戦も1段階弱い |

出自によって会話や結末の一部が変わる（台本の各行の `if:isO('…')`）。

賭け・流儀・勝敗（`startStage` / `showStageResult`）。

- 第二章・第三章の対局前に、ボスが賭けを持ちかける（受ける／流す）。受けるとボスが最強（レベル3）になる
- 第五章・第六章は賭けが必ず付く（`forceWager`）
- 1位は「完全勝利」で称号。ボスより上の順位は「辛勝」で突破。ボスより下は「敗北」
- 賭けを受けて負けるとバッドエンド。「あの日に戻る」でやり直せる
- 賭けを受けたうえで「流儀」（各戦の `cond`）を満たすと、ボスの秘密が語られ翠ノートに載る。第二章の3人からはスキルも託される（ハヤト＝透視、シズカ＝千里眼、ゲン＝神引き）
- 各戦を突破すると幕間の会話がある。二度目の突破では別の幕間（`after` / `after2`）

ボスの特別な打ち方。

- カラス・堂本・鷲尾は配牌を積み込む（`rigHand`）。ツモも一定の確率で仕込む（`CHEAT_DRAW`＝レベル1〜3で15%／30%／45%、`godPick`）
- プレイヤーが千里眼を使っている間は、ツモを仕込めない（`drawStep`）
- 鷲尾は `readHand`。プレイヤーがテンパイ中は、その待ち牌を切らない。鷲尾自身がリーチ中は読まない（`chooseBestDiscard`）

結末（`ENDINGS` / `showEnding` / `showDarkEnding` / `EPILOGUE`）。

| 場面 | 条件 | 結末・称号 |
|---|---|---|
| 第四章 | マスターより下の順位 | 閉店 |
| 第四章 | 「新しい翠」の道で突破 | 新しい翠 |
| 第四章 | 「翠を守る」の道で1位、かつ秘密3つ以上（ハヤト・シズカ・ゲン・レンの流儀のうち。`flagCount`） | 翠の主（真エンド。称号「翠の主」） |
| 第四章 | 上記以外で突破 | 翠の頂 |
| 第五章 決戦 | 1位 | 黒い手、払う（称号「翠の守り手」） |
| 第六章 決戦 | 1位 | 白い塔、崩れる（称号「翠の灯」） |

- 第五章・第六章の決戦で、ボスより上だが1位でない時は「まだ、終わらない」でやり直し
- 第四章の結末には後日談がある。真エンドは出自ごとに締めが変わる

翠ノート（`NOTES`、`showNotes`）。

- 全16ページ。出自1、秘密9（ハヤト・シズカ・ゲン・レン・クロダ・カラス・堂本・ミナト・ハヤト二度目）、結末6
- 開いたページは `mjHero` の `notes` に入る
- 「物語を最初から」（`resetStory`）で主人公を変えられる。道場の記録は残る

会話シーン。

- 全画面のビジュアルノベル風（id `vn`）。一文字ずつ表示し、タップで送る。選択肢あり（関数 `say` / `choose` / `vnShow`）
- 背景は SVG で描く5種（`SCENE_NAME`: 雀荘 翠／翠 閉店後／駅裏の路地／白い塔 最上階／雀荘 黒牌、関数 `sceneSVG`）
- 立ち絵は影絵風の SVG（`portraitSVG`）。対局の時だけ卓に戻り「○○ 戦」のカットインで始まる

#### 自由対局

- CPU 3人は常連（ハヤト・シズカ・ゲン・マスター）からランダム。`mjStage` が4以上ならレン・クロダも候補に入る
- CPU の強さはメニューで選ぶ（`CPU_LEVELS`、保存キー `mjCpuLv`）。物語の相手には効かない
- キャラごとに卓上で吹き出しの掛け合いをする（`BANTER`。開始・リーチ・和了・放銃・鳴き・流局・南場入り）
- スキル3種はすべて使える
- 上部「新局」でその局を配り直せる（点数・本場・供託は局の開始時に戻る）

#### みんなで対戦

この端末で交代して遊ぶ（`startHot`、`MODE='hot'`）。

- 2〜4人。空いた席は CPU
- 人の番（鳴き・ロンの確認を含む）になると名前を全画面に出す（id `curtain`）。タップするまで手牌は伏せたまま
- 鳴きの確認は「ポン・チー・ロンを聞く／聞かない（ロンは自動）」を選べる
- 通信はしない

オンラインで遊ぶ（部屋主は `MODE='host'`、参加者は `MODE='guest'`）。

- 部屋を作ると6文字の部屋コードと招待リンクが出る。最大4人、空いた席は CPU
- 部屋主の端末がゲームを進め、参加者は操作だけを送る。不正な操作は部屋主側で弾く
- 参加者の持ち時間は打牌40秒（自分のリーチ中は12秒）、鳴き15秒。過ぎるとツモ切り／スルー
- 抜けた席は CPU が引き継ぐ。同じ端末から入り直すと元の席に戻る
- 部屋主が抜けても、残った人の端末が部屋主を引き継ぐ
- つながりにくい回線向けに中継サーバー（TURN）を設定できる
- 定型文8種だけを送る「ひとこと」チャットがある（`CHAT`）
- 詳細は #0003 と README の「オンライン対戦の仕組み」「中継サーバーを使う手順」

みんなで対戦の共通点。スキルゲージは出さない。卓上の掛け合いも出ない。

#### 初心者向けの助け

- 初心者モード（上部のチェック、id `begChk`。最初からオン）: 手番の案内、おすすめの捨て牌（`recommendDiscard`）、鳴きの説明。相手のリーチ中はおすすめが現物に変わり、押し引きの案内が出る
- 「いまの手を見る」（`analyzeHand` / `showHandModal`）: 何シャンテンか・待ち・フリテン、できている組、狙える役、おすすめの捨て牌と理由
- 画面の見方ツアー（`TOUR_STEPS` 10ステップ、`screenTour`）: 「はじめての和了」レッスン（第一章 第二節）の最初に一度だけ自動で出る。メニューから再表示できる
- おたすけモード（`ASSIST`、保存キー `mjAssist`）: 物語の相手が1段階弱くなり、スキルゲージが1.5倍溜まる
- ルールブック（`showHelp`）: はじめに／役（牌の例つき）／鳴きと守り／点数／用語 のタブ
- 和了画面で役名をタップすると説明が出る（`YAKU_DESC`）
- 対局速度は「じっくり／標準／はやい」（`SPEEDS`）。最初は「じっくり」

#### 対応ルールと役

- 4人打ちの半荘（東場・南場）。持ち点25,000点。誰かが0点未満になると終了（`endCheck`）
- ツモ・ロン、立直（一発・裏ドラ・ダブル立直）、ポン・チー・カン（暗槓・加槓・大明槓）、槍槓、ダブロン、フリテン
- 赤ドラは5萬・5筒・5索が各1枚（`REDABLE`）。メニューでオン・オフ（次の局から）
- リーチ中にあがり牌を引いたら自動でツモ
- 流局時はノーテン罰符（計3,000点）をやり取りする（`ryuukyoku`）
- 役: 立直・一発・門前清自摸和・平和・断幺九・役牌（白・發・中・場風・自風）・一盃口・二盃口・三色同順・三色同刻・一気通貫・対々和・三暗刻・七対子・混一色・清一色・混全帯幺九・純全帯幺九・混老頭・小三元・海底摸月・河底撈魚・嶺上開花・ダブル立直・槍槓・国士無双・大三元・四暗刻・字一色・清老頭。ドラ・裏ドラ・赤ドラ
- 符計算（`computeFu`）と点数（`effBase` / `payments`）。13翻以上はすべて役満（ダブル役満はない）

#### CPU の性格と強さ

性格（`CHAR_STYLE`）はキャラごとに決まっている。`call`＝鳴き派（ハヤト・カラス）、`defense`＝守り派（シズカ・ミナト）、`riichi`＝リーチ派（ゲン・堂本）、`normal`（マスター・レン・クロダ・鷲尾）。

強さ（`CPU_LEVELS`。自由対局とみんなで対戦の CPU）。

| 強さ（id） | 打ち方の要点 |
|---|---|
| やさしい（`easy`） | ときどき最善でない牌を切る。守らない。テンパイしてもリーチを半分見送る。安いロンをたまに見逃す（`aiMissesRon`） |
| ふつう（`normal`） | 性格に沿って効率よく打つ。リーチされたら手が遠い時は降りる（`chooseBestDiscardCore`） |
| つよい（`hard`） | 見えている枚数で受け入れを数える。危険度（`dangerOf`）で安全な牌を選ぶ。残り枚数の多い待ちを選び、5翻以上はリーチせず黙って待つ（`aiDiscard` / `aiTenpaiChoice` / `aiPrefersDama`） |
| 鬼（`oni`） | つよい＋ドラ・赤・役牌の対子を残す。高い1シャンテンは押す。4翻以上は黙って待つ |

物語の相手は強さの設定を使わない。`p.level`（1〜3）と性格で打つ（`castStage` / `bossLevel`）。

#### スキル

| スキル（id） | 消費 | 効果 |
|---|---|---|
| 透視（`peek`） | 30 | 山の次の3枚（これから誰かが引く牌）が見える |
| 千里眼（`foresight`） | 45 | 相手のテンパイが分かる。1局1回。イカサマのツモ仕込みを止める |
| 神引き（`god`） | 80 | 自分の次のツモが、手の進む牌になる（進む牌がなければ普通に引く）。1局1回 |

- 使えるのは自分の打牌の番だけ。ゲージは打つと溜まる（`gaugeAdd`、上限100）
- 第二章〜第四章では、託されたスキルだけ使える（`skillLocked`）。第五章・第六章は全部使え、ゲージが1.5倍
- レッスン中とみんなで対戦中はゲージを出さない

#### 演出と音

- 打牌が河へ飛んで着地する（`flyTile`）。リーチ・ツモ・ロン・鳴きの宣言は大きな文字で出す（`flash`、id `callflash`）。スキルと物語の対局開始はカットイン（`cutin`）
- 和了画面は、手牌が1枚ずつめくれ、役が順に出て、点数がカウントアップする。タップで省略できる（`showResult`）
- 点数の増減の表示（`showDeltas`）、紙吹雪（`confetti`）
- 牌の絵は SVG で描く（`faceSVG`）。画像ファイルは使わない
- 効果音と BGM は WebAudio でその場で作る（`sfx` / `beep` / `THEMES` / `bgmPlay`）。音声ファイルはない。BGM は場面ごと（store / storeNight / alley / tower / kurohai）と対局中（match）・ボス戦（boss）
- 音はメニューと会話画面でオン・オフできる（`setSound`、保存キー `mjSound`）

### データの保存

- 保存先は端末のブラウザの localStorage だけ。サーバーには送らない
- 読み書きは `lsGet` / `lsSet` を通す（失敗しても止まらないよう try で包んでいる）
- 端末ごと・ブラウザごとに別。README では「ホーム画面のアプリとブラウザでも別」と書いている
- 引き継ぎ・バックアップの機能はない

| キー | 保存している内容 |
|---|---|
| `mjHero` | 主人公（JSON）。`name` 名前、`origin` 出自、`skills` 託されたスキル、`route` 岐路の道（`protect` / `neo`）、`notes` 開いた翠ノート |
| `mjZero` | 第0章の進み（クリアした節の数） |
| `mjStory` | 第一章の進み（クリアした節の数） |
| `mjStage` | 第二章以降の進み（`storyPath()` の何番目まで進んだか） |
| `mjTitle` | 称号 |
| `mjFlag_<id>` | 流儀を制した印。id は hayato / shizuka / gen / ren / kuroda / karasu / domoto / minato / hayato2 / washio |
| `mjInter_<id>` / `mjInter2_<id>` | 突破後の幕間を見た印（1回目／2回目） |
| `mjEnd_<id>` | 見た結末。id は true / top / neo / close / dark / tower。書き込むだけで、読み出しには使っていない（翠ノートは `mjHero` の `notes` で判定） |
| `mjLesson_<id>` | 道場のレッスンのクリア（id は `LESSONS` の id） |
| `mjTour` | 画面の見方ツアーを見た |
| `mjHelpSeen` | 初回の案内を済ませた（次からは自由対局の卓で起動） |
| `mjCpuLv` | 自由対局の CPU の強さ |
| `mjSpeed` | 対局速度（slow / normal / fast） |
| `mjSound` | 音のオン・オフ |
| `mjRed` | 赤ドラのオン・オフ |
| `mjAssist` | おたすけモード |
| `mjHotN` / `mjHotNames` / `mjHotCalls` | この端末で交代：人数・名前・鳴きの確認 |
| `mjVsLv` | みんなで対戦の CPU の強さ |
| `mjNetName` | オンラインで使う名前 |
| `mjIce` | 中継サーバーの設定（Metered の認証情報URL、または接続情報の JSON） |
| `mjChatOff` | ひとことチャットを表示しない |
| `mjRejoin_<部屋コード>` | 再入室用の合言葉・席・部屋の世代。sessionStorage にも同じものを入れる |

- 「物語を最初から」（`resetStory`）は物語のキーを消す。道場の `mjLesson_` と設定は残る。序章で主人公を決めた時（`showPrologue`）も一部を消す
- 初心者モードのチェック（`begChk`）は保存しない。読み込み直すとオンに戻る
- `mjIce` に Metered の URL を貼ると、URL に含まれる API キーも端末に平文で残る

### 通信と外部リソース

ひとり用（道場・物語・自由対局）と「この端末で交代」は通信しない。外部から読み込むものもない。

- 書体は端末に入っている書体だけ（ヒラギノ・游ゴシック・メイリオなど）。Google Fonts などの Web フォントは使っていない
- 牌・背景・立ち絵・アイコンは SVG をコードで描く。音は WebAudio で作る

オンライン対戦を選んだ時だけ、次と通信する。

| 相手 | 用途 | コード上の場所 |
|---|---|---|
| cdnjs（PeerJS 1.5.5） | 通信部品の読み込み。SRI（改ざん検知）付き。オンラインを選んだ時だけ読む | `PEER_URL` / `PEER_SRI` / `loadPeer` |
| PeerJS の公開仲介サーバー | 部屋ID（`suimj-room-` ＋部屋コード）の登録と接続の仲介。コードでは接続先を指定せず PeerJS の標準を使う（README では 0.peerjs.com） | `new Peer(…)`、`ROOM_PREFIX` |
| STUN（Google・Cloudflare） | 端末どうしの経路を調べる | `ICE_BASE` |
| PeerJS の公開中継（turn.peerjs.com） | 直接つながらない時の中継 | `PEERJS_TURN` |
| 利用者が設定した中継（Metered など。任意） | 会社・学校の回線などでの中継。Metered の URL なら認証情報を取りに行く | `mjIce` / `iceConfig` / `fetchTurn` / `METERED_RE` |
| 相手の端末 | 対局のやり取り（WebRTC で直接） | `hostOnData` / `guestOnData` |

- 部屋主は参加者ごとに、その人の手牌だけが入った状態を送る（`projectFor`）。他人の手牌・山の並び・裏ドラは送らない
- 部屋主が設定した中継の接続情報は、参加者にも渡す
- 通信の版は `NET_PROTO`（2）。版が違う端末は待合室で弾く
- プライバシー: オンライン時は、仲介サーバー・相手の端末・中継の事業者に IP アドレスなどの接続情報が渡る。開発側では何も保存しない。App Store で「データを収集しません」を選ぶなら、サポートページと申請メモにこの点を書く（README の指摘）
- チャットは定型文の番号だけを送る。自由入力はない

### 技術構成とコードの地図

全体の作り。

- 素の HTML・CSS・JavaScript。ビルドなし、フレームワークなし。外部ライブラリはオンライン時の PeerJS だけ
- `index.html` の並び: 先頭の `<meta>` と `<style>`（CSS）→ 画面の骨組み（id `topbar` / `table` / `seat0`〜`seat3` / `center` / `bottomHand` / `myHand` / `actions` / `skillbar` / `overlay`・`modal` / `curtain` / `vn` / `coach` / `cutin`）→ `<script>` 1本
- JavaScript は見出しコメント `/* ===== 名前 ===== */` で区切ってある。検索の目印に使う
- 主な全体の変数: `G`（対局中の状態）、`MODE`（null＝ひとり / hot / host / guest）、`MP`（みんなで対戦の席）、`VIEW`（画面の下に出す席）、`NET`（オンラインの状態）、`HERO`（主人公）、`tut`（レッスン・物語の進行中の情報）、`SKILL`（ゲージ）
- 牌の番号: 0-8 萬子、9-17 筒子、18-26 索子、27-33 字牌（東南西北白發中）。赤ドラは番号＋0.5（`nt` で通常の番号に戻す、`isRed` で判定）
- 席の操作者は `G.ctl[席]`（local / cpu / remote）。`isHuman` / `ctlOf` で判定する

### PWA・iOS

PWA。

- `manifest.json`: 名前「麻雀 4人打ち」、短い名前「麻雀」、`display: standalone`、`orientation: portrait`、`start_url: ./`。アイコンは 192・512・512（maskable）
- `sw.js`: キャッシュ名は `mahjong-v5`。インストール時に HTML・manifest・アイコンをキャッシュする
- HTML はネットワーク優先。毎回サーバーに確かめ（`cache: 'no-cache'`）、つながらない時だけキャッシュを返す
- HTML 以外の同じサイト内のファイルはキャッシュ優先。キャッシュにあれば取り直さない
- 別ドメイン（CDN・仲介サーバー・中継サーバー）への通信は触らず、そのまま通す
- 登録は `index.html` の末尾。`localhost` と `127.0.0.1` では登録しない（別アプリのキャッシュと混ざるため）
- 公開は GitHub Pages（リポジトリ `kiyotake1229/mahjong` の main）。push すると数十秒で反映（README）。2026-09-15 に本番の `index.html` を取得し、コミット 7da34fc と同じ内容であることを確かめた

iOS。

- 未着手。`ios-app/` はない
- 作る時は `habit/ios-app/` を雛形に Capacitor で包む（README と共通ルール）

### 既知の制限・注意点

README との食い違い・README にない点。

- オンラインの持ち時間は、README では「打牌40秒」。実装では参加者が自分のリーチ中は12秒（`netTurn`）
- `sw.js` のコメントは「キャッシュ優先＋裏で更新」。実装はキャッシュにあると取り直さない。アイコンや `manifest.json` を変えた時は `CACHE` の名前を上げないと、入れ済みの端末に届かない
- `manifest.json` の説明文は「CPUと対戦する4人打ち麻雀。初心者ガイド付き。」のまま（みんなで対戦に触れていない）。テーマ色も `manifest.json`（#0b3d27）と `index.html` の meta（#05070f）で違う

実装で気づいた点（どれも実機では未確認）。

- 翠ノートの数え方: 鷲尾の決戦に1位で勝つと、`showStageResult` の `addNote(fk)` で `washio` がノートに足される（`fk` は `st.flagKey||st.boss`）。`NOTES` に `washio` のページはない。メニューの「翠ノート n/16」が実際のページ数より1多くなり、全部集めると 17/16 になりうる
- `mjFlag_washio` は `resetStory` の消去一覧にない。物語を最初からにしても、鷲尾戦の流儀が達成済み表示のまま残りうる
- `mjRoute` は消去一覧にだけあり、どこでも保存していない（道は `mjHero` の `route`）
- 道場から「はじめの一歩」を主人公未設定のまま始めると、出自「学生」・名前なしで保存される（`showDojo` 内）。その後は序章（名前と出自の選択）を通らない。意図した動きかは未確認
- `index.html` の先頭に `<!DOCTYPE html>` がなく、`<meta charset>` から始まる。表示への影響は未確認

仕様上の制限。

- データは端末の中だけ。機種変更やブラウザのデータ消去で進みが消える
- ルールで対応していないもの（ソースに処理がない）: 途中流局（九種九牌など）、流し満貫、天和・地和、包（パオ）、西入。ダブル役満もない
- オンライン対戦: 途中から新しい人は入れない（抜けた人の再入室はできる）。部屋主の交代中（数秒〜20秒）は操作できない
- 部屋主の交代は `crypto.subtle` が使える環境だけで動く（`MIG_OK`）。HTTPS か localhost なら使える。LAN の IP アドレスを http で開いた場合は交代しない
- オンライン対戦は PeerJS の無料公開サーバーに頼っている。止まると新しい部屋を作れない。公開中継（turn.peerjs.com）は混むと使えない
- 音はブラウザの決まりで、最初のタップの後に鳴り始める
- 自動テストはない。確認は手動（ブラウザの複数タブで端末を代用するなど。#0003 参照）
- Claude Artifact で開いた場合のオンライン対戦は未確認（Artifact は外部との通信をほぼ止める）
