# プライバシーマニフェストと暗号化の申告（雀荘 翠）

- 管理番号: #0049
- 種類: ENH（機能改善）
- 対象: iOSアプリ（IOS）
- 作成日: 2026-11-06
- 関連: #0019（iOS アプリの土台）

## 概要

App Store へのアップロードで求められる申告を iOS アプリにそろえた。プライバシーマニフェスト（`PrivacyInfo.xcprivacy`。トラッキングなし・収集データなし・「理由の申告が要る API」の利用理由）をアプリに入れ、暗号化を使っていない申告（`ITSAppUsesNonExemptEncryption = NO`）を足した。GitHub Actions のビルド確認（Xcode 26）で、ビルドが通ることと、できたアプリにこれらが入っていることを確かめた。

## 対象ファイル

- `ios-app/ios/App/App/PrivacyInfo.xcprivacy`（新規）
- `ios-app/ios/App/App.xcodeproj/project.pbxproj`（App ターゲットの Resources に登録）
- `ios-app/ios/App/App/Info.plist`（`ITSAppUsesNonExemptEncryption` を追加）
- `.github/workflows/ios-build.yml`（新規。iOS のビルド確認）
- `README.md`（iOS の行）
- `ios-app/岩崎さんへの引き渡し手順.md`（プライバシーの章に1行）

## 変更内容

- **プライバシーマニフェスト**（`PrivacyInfo.xcprivacy`）: トラッキングなし（`NSPrivacyTracking = false`）、トラッキング用のドメインなし、収集データなし（App Store Connect の「データを収集しません」と同じ）。申告した「理由の申告が要る API」は次のとおり
  - UserDefaults（`NSPrivacyAccessedAPICategoryUserDefaults`、`CA92.1`: アプリ自身のデータの読み書き）
  - 収集データは空にしてある。オンライン対戦では、接続の仲介（0.peerjs.com）・中継サーバー・相手の端末に IP アドレスなどの接続情報が渡るが、開発側は何も受け取らず保存もしない（README の「オンライン対戦の仕組み」のプライバシーの項）。いまの App Store の申告「データを収集しません」に合わせた。申告を変えるときはマニフェストもそろえる
- **申告の決め方**: アプリが使う部品（Capacitor 7.6.9 本体、`@capacitor/app` 7.1.2、`@capacitor/haptics` 7.0.5）を `ios-app/package.json` と `package-lock.json` で確かめ、それぞれの iOS 側のソースを調べた。この3つのソースを確かめたところ、「理由の申告が要る API」を直接使っているものは無かった（Capacitor 本体は自分用のマニフェストを持っていて、中身は空）
  - 全アプリ共通の決まりとして UserDefaults（`CA92.1`）は必ず申告する。理由の申告が足りないと、アップロード時に ITMS-91053（理由の申告が無い）で止められる（2024年5月から）。Apple が見ているのは「使っているのに申告が無い」ことで、多めに申告して止められることはない。あとから `@capacitor/preferences` などを足したときの申告漏れも防げる
  - `@capacitor/filesystem` を足すときは、ファイルの日時（`NSPrivacyAccessedAPICategoryFileTimestamp`、`C617.1`）も足す。足し忘れるとビルド確認が失敗する（下記）
- **Xcode のプロジェクトへの登録**: 手元に Xcode が無いため、CocoaPods に入っている xcodeproj（Ruby）で App ターゲットの Resources に追加した（そなえ帳と同じ方法）。保存のときに、中身が空の `packageReferences` の項目が外れることがある（Swift Package は使っていないので影響なし）
- **暗号化の申告**: `Info.plist` に `ITSAppUsesNonExemptEncryption = NO`（`<false/>`）を足した。このアプリは「みんなで対戦」のオンラインのときだけ通信するため、足す前に中身を確かめた
  - 通信は、PeerJS（cdnjs から読み込む）・接続の仲介（0.peerjs.com）・STUN/TURN・相手の端末との WebRTC。暗号化はどれも iOS に入っている WebKit（WKWebView）の HTTPS・WebSocket（wss）・WebRTC（DTLS）がしているだけで、アプリが自分で暗号の仕組みを持っているわけではない
  - Apple の決まりでは、OS に入っている暗号化だけを使うアプリは輸出規制の書類が要らない（免除）。この場合は `NO` を入れてよい。アップロードのたびの暗号化の質問も出なくなる
  - 今後、独自の暗号（自前の暗号化ライブラリ・ネイティブの暗号処理など）を足すときは、`YES` に変えて App Store Connect の質問に答え直す
- **ビルド確認（GitHub Actions）を新しく作った**: `index.html` や `ios-app/` を push するたびに、macOS のランナーで `npm ci` → `sync-web` → `cap sync`（pod install）→ シミュレータ向け（Debug）と実機向け（Release）の署名なしビルドを行う。Xcode は **26 に固定**（Capacitor 7 は UIScene に対応していないため、Xcode 27 の SDK ではビルドしない。そなえ帳と同じ）
- **ビルド確認で毎回確かめること**（`.github/workflows/ios-build.yml`）:
  - Xcode のプロジェクトで `PrivacyInfo.xcprivacy` が App ターゲットの Resources に入っていること、ファイルが正しい形式であること
  - できたアプリ（`App.app`）に `PrivacyInfo.xcprivacy` が入り、トラッキングなし・トラッキング用ドメインなし・収集データなしであること
  - UserDefaults（CA92.1）の申告があること。`CapacitorPreferences` が入っていれば UserDefaults（CA92.1）、`CapacitorFilesystem` が入っていればファイルの日時（C617.1）の申告が無いと失敗にする（プラグインを足したのにマニフェストを直し忘れるのを防ぐ）
  - `Info.plist` の `ITSAppUsesNonExemptEncryption` が false、Bundle ID が `work.ltv.sui`、使っているプラグインのフレームワークが入っていること
- 作業は Dropbox の外の作業用コピーで行い、`node_modules/` は Dropbox に置いていない
