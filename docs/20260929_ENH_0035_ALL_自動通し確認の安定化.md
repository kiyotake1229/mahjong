# 自動通し確認（tools/lessons.js）の安定化

- 管理番号: #0035
- 種類: ENH（機能改善・品質）
- 対象: プロジェクト全体（ALL）。`tools/lessons.js`
- 作成日: 2026-09-29
- 関連: #0028（道場と物語の自動通し確認）、#0032（1回目の通しで終節が時間切れになった件）

## 概要

道場・物語の自動通し確認が、アプリに問題がないのに「通らない」と出ることが2種類あった。どちらも原因を特定して直した。

1. 第一章の終節（一局勝負）で自動の打ち手が負けると、「惜しい」の画面の「もう一度」を押さない決まりのため「雀荘へ」を押して章の一覧に戻り、200秒の時間切れになっていた。勝てば通るので、結果が運で変わっていた
2. 手元の Chrome（headless）自体が途中で落ちると、ツールごと止まっていた（2026-09-28 に1回発生。「Target closed」）

## 対象ファイル

- `tools/lessons.js`
- `tools/README.md`

## 変更内容

- 終節：負けて「もう一度」の画面まで進んだら、流れの確認としては通過にする。第二章以降の戦ですでに使っている判定と同じ。結果の行に「（負けて「もう一度」の画面まで）」と出る
- Chrome が落ちた時：開き直して、その項目を1回だけやり直す。「再起動　〇〇：ブラウザが落ちた（理由）」と必ず表示し、最後の行にも回数を出す。アプリの例外（`window.onerror`）は今までどおり NG。開き直しても落ちた項目は NG
- 各項目の前に途中の対局の保存（`mjSaveGame`）を消す。前の項目の対局が残っていると「途中の対局を消して、新しく始めますか？」の確認が出て、ツールがキャンセルで閉じていた（結果には影響しないが、毎回5回出ていた）
- 通過した項目にページの使用メモリ（MB）を添える。項目を重ねて増え続けるならメモリの漏れを疑える
- 開き直しの確認用に `LESSONS_CRASH_TEST=<項目の番号>`（その項目の1回目の3秒後に Chrome を強制終了する）
- 1項目の処理を `runItem`、ブラウザを開く処理を `openBrowser` に分けた（開き直しで同じ手順を使うため）

確認した内容：

- `LESSONS_CRASH_TEST=17 node tools/lessons.js 200 ch 17`：第一章 第7節の途中で Chrome を落とす → 「再起動」と表示 → 開き直して第7節が通過 → 終節は負けて「もう一度」の画面までで通過 → 最後の行「すべて通過（途中でブラウザが1回落ち、開き直した）」
- 全項目の通し（道場8・第0章3節・第一章8節）：すべて通過、確認ダイアログ0件（修正前は5件）、使用メモリは各項目10MBで増えない
